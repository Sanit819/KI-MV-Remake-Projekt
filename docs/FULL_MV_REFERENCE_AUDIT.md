## 新参考实际展示了什么

新参考延续开源片的主要结构：警告片头、对象/世界建立、聊天界面中的几何变化、设置控件和历史剪纸、有限色物件与龙娘、对方离线、红色错误堆积、纯代码执行与计数、强烈的角色/字形高潮、心形段落、图像缩回聊天消息、界面清空和等待输入。

画面主色由原参考的橙换成紫黑。大多数龙娘形象以无脸剪影呈现，紫色、米白、近黑在衣裙、头发和背景中交替；高潮使用有眼睛的特写、复制的窗口、前景大字以及短促的错位/撕裂。末段心形内出现 GPT 与另一名角色靠近，随后这幅完整图像缩为聊天中的一张图；接触表能看到反馈为零的状态和最后的空白输入框。它并未表现我们企划中「新的独立输入真的进入、她认出、放松、双方继续画」这串连续动作。

可吸收的做法：统一紫黑、人物与大字和几何物轮换占据画面；同一标志在饰物、界面和抽象场景间建立联系；终端的重复条目和增大的数字形成压力；心形等负空间让人物与主题有共同轮廓。需要避免：简单替换工程角色和颜色、让大量细线缩成难辨纹理、把整片情绪寄托在同一张立绘的推拉、以清空界面结束我们已经确认的温暖故事。

| 大块面 | 第一眼可认轮廓，第二墨色表现明暗，不靠小线描或柔光 | 以v05的紫色中间墨、浅紫墨、近黑负形统一角色；物件应能不看标签认出来；人物阴影不随镜头任意变色 |
| 字体语义 | 衬线是AI，无衬线是用户与界面，等宽是系统 | ASTRA的原创表达、暖金回应、规则/终端分别使用固定字体角色；字号和字幕带在同段稳定 |

| 透明与图标 | 加载清理低alpha残点，人物分墨版，饰物与全片母题一致 | 新姿势的GPT结饰直接随角色由ImageGen画入，孔洞、垂穗与头发共同构图；无圆盘、无外圈；禁止独立SVG/标准图标叠加和旧v04素材回流 |
| 节奏 | 切点落拍/半拍，镜内动作可用实测起音 | 使用本项目 `calibrated_timeline.json` 和声音分析结果；不能套用参考默认第0拍0.344秒及其5秒片头 |
| 运动 | 缓动、错开开始、次级动作；不能全靠透明淡入淡出 | 路径生长、角色明确动作、镜头与前景错速、物件形状接力；每镜有推进事件 |

| 确定性 | 每帧仅由时间决定，没有跨帧随机状态 | 回放、两笔动作与转场都用显式时间曲线；重复渲染同一帧一致，方便逐镜检查 |
| 性能 | 像素读取、墨版与路径构建在载入阶段完成 | 渲染期不调用逐帧 `getImageData`，不在60fps主循环重分版 |

角色 v05 是唯一当前风格基准，不能将更早对v04的「基本满意」延用为当前批准。新增图须保留刘海遮脸比例、脸部暗色负形、龙角折面和曲率、发侧绘入结饰的位置、少量菱形领口结构；不回用旧版亮紫眼、奶油肤色、长裙腰带或后贴标设计。情绪优先通过头倾、肩线、手势与动作停顿表达。左右手以角色自身的左右定义，不对生成角色整体镜像来凑朝向。

## 修复轮比初版更重要的一项纠正

`PROMPT_v4_fix.md` 明确认为高潮中的8/12fps持续降帧和人物缓慢推近，看起来像播放卡顿，不能表达足够的冲突。修复后要求60fps连续运动：角色底板稳定，背后的旋转世界、线框、墨版被鼓点弹开再滑回、黑墨内部代码、前景字符和速度变化共同承担运动。

我们应继承「故障是短事件，连续运动不断」这一点。参考修复轮曾允许短促的脸部撕裂和RGB错位；本项目应优先保持用户重视的脸、手、透视与六环饰物可辨，把剧烈断裂放到规则、边框、代码和环境上。高潮强度靠动作方向、构图压缩、节奏和规模变化建立，不能只堆全屏白闪。

参考中的每秒大面积亮度往返不超过3次，是值得复查的工程约束；任何自动检查都只是风险筛查，不代表医疗安全认证。若本项目不采用高频全屏闪光，不应为了模仿参考而额外添加警告片头及改变既定全曲时长。

## 全片一致性检查门槛

- 静帧：54镜各看至少开端/中段/动作完成点；有脸、有手、翼根、尾部与饰物的镜头另看放大图。
- 动作：关键情绪段看连续片段，不能只凭联系表判断认出与放松是否成立；高潮不能出现意外8/12fps卡顿。
- 衔接：旧星/新星坐标和身份、紫笔/金笔方向、跨镜轴线、角色饰物位置一致；转场必须由镜头里的物件或动作发起。
- 风格：全片采用v05同一调色配置、纸纹尺度、字体角色、轮廓粗细和墨版处理；新素材不混入旧v04有脸造型、独立贴标、写实渐变或旧版圆章。
- 音乐：按现有官方原版轨道核对动作帧；外部参考时间只能作为构图研究，不能覆盖本项目的已校准时间。
- 输出：完整预览检查后导出4K60；读取实际编码尺寸、帧率、总帧数、时长，完整解码和音轨对齐。若仍有资产或剧情动作未实现，列明，不把导出成功等同艺术验收。
