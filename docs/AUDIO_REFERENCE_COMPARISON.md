# 用户 FLAC 与官方 MV 参考音轨比较

2026-11-07。输入为用户桌面 `C:/Users/auscar/Desktop/07 太陽系デスコ.flac`，参考为本地 `source/audio.m4a`（此前从用户指定 B 站 MV `BV1UfZ2YwEP5` 获取）。这是文件探测及信号计算，没有进行耳听或歌词逐字对时。

## 结论与时间映射

两份音频在本次计算中高度对应，**参考 MV 音轨比用户 FLAC 的相同内容晚约 84 毫秒**。14 个分散的 10 秒窗口全部得到同一个 8 kHz 分析网格偏移：673 个采样，即 0.084125 秒；没有观察到跨窗口时差漂移、明显的插入／删除造成的时差跳变或整体变速。

映射方向必须保持为：

```text
参考 MV 音轨时刻 ≈ 用户 FLAC 时刻 + 0.084 秒
用户 FLAC 时刻 ≈ 参考 MV 音轨时刻 − 0.084 秒

例：FLAC 100.000 秒的内容，匹配参考音轨 100.084125 秒。
```

因此，后续若把参考 MV 的音轨事件时码转到用户 FLAC，应减去约 84 毫秒。这个偏移约为 30 fps 的 2.52 帧，不应直接忽略，也不应粗暴取成固定 2 帧或 3 帧后宣称精确对齐。**0.084125 是分析网格的峰值，不是对演唱词界、感知同步或原始录制采样级精度的保证。**

这支持“总体录音内容与编排相对应”的判断，不能证明二者是无损同一、同一母带、同一混音或所有细节完全相同。此处也没有自动生成歌词句界。

参考音轨标称长 0.136916 秒；解码到统一分析网格后长 0.137125 秒。这一差值不能直接解释成多出一段音乐。

加上测得的偏移后，FLAC 终点对应参考音轨 203.284125 秒。参考音轨在此之后仅剩 **0.053 秒**分析样本，RMS 为 **−107.33 dBFS**，最大绝对幅值约 0.0000731。它是极低电平尾部，支持“近静音／类似填充的尾巴”这一解释，不能写成严格数字全零，或未经编码链证据就断言具体由哪一级编码器产生。

10 毫秒 RMS 窗口的末端活动也相符：超过 −60 dBFS 的最后窗口分别结束于 FLAC 201.23 秒、参考音轨 201.31 秒；超过 −80 dBFS 时分别为 202.87、202.96 秒。阈值只是客观电平测量，不是听感静音判断。

## 方法与复核

1. FFprobe 只读音频流参数，显式选择 `a:0`，不把 FLAC 内嵌封面当作视频内容。
2. FFmpeg 将两个输入分别解码到 `.cache/audio-comparison/` 下的 8 kHz、单声道 float32 分析副本。原文件不转换、不重写、不改变采样率／位深。
3. 用 10 毫秒 log-RMS 包络，将 FLAC 15–185 秒在参考轨上作 ±10 秒粗搜索，得到约 +80 毫秒。
4. 用 NumPy FFT 计算 14 个分散窗口的归一化波形互相关，在粗位置 ±2 秒内细搜。8 kHz 的网格为 0.125 毫秒。相关索引与偏移方向用合成延迟信号作断言校验。
5. 记录全重叠相关、不同电平阈值的末端活动、对齐终点之后的参考尾部电平。读取前后对两个输入计算 SHA-256，结果保持不变。

完整参数、逐窗口结果、输入 SHA-256 和限制在 [audio-reference-comparison.json](../analysis/audio-reference-comparison.json)。复算脚本为 [compare_provided_audio.py](../tools/compare_provided_audio.py)：

```powershell
python tools/compare_provided_audio.py --provided 'C:/Users/auscar/Desktop/07 太陽系デスコ.flac'
```

复算仅会更新本比较 JSON 与缓存分析副本，不会改动输入 FLAC／AAC。仍需在正式制作阶段结合实际听辨检查重要起音和转场，不能把本报告改写成歌词已逐句精确对齐。
