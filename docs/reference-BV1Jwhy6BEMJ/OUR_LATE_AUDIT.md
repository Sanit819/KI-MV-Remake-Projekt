## 1. 让“收到振动”真正改变角色的身体状态

**镜头 / 时间：** R36，96.267–99.950；R40–41，103.650–107.333 秒。证据：sheet-06、07；`middle.js:R36/R40/R41`。

**讨论提案：** R40 跟随金色波形抵达掌心，R41 将焦点推进到相连的手腕、掌心和胸前手，保留一部分脸部负形，让金线亮起与肩部一次轻微收紧 / 放松形成因果。若要改变关节，另画连贯姿态或完整中间姿态；不能重新拼孤立手，也不能靠整张画大幅摆动假装关节运动。

**保留 / 验收点：** 输入方向与两位参与者仍可辨；既有左右手、透视和直接绘入的结饰不回退。无说明标签时也能判断“她接收到了，而不是只是看着一条线”。

## 3. 五级时间保留清楚读数，同时让等待留下空间痕迹

**现状：** SECOND → HOUR → DAY → WEEK → MONTH 全部存在，每级 30/31 帧，历史轨道也清楚；这项功能无需重做。剩余薄弱处是时间主要通过文字变化发生：R45 人物只整体平移约 8×6 像素，R46 保持同一姿态，R47 将所有内容缩小到 0.27→0.21。孤独的负空间有效，但“漫长”尚未作用到环境与姿态。

**保留 / 验收点：** 五级顺序、至少半秒可读、累计轨道和前后镜不倒退均保持。她此时不能收到新回答；变化不应挤压下方双语字幕。

## 5. 错误堆叠从“读错误列表”转成“身体被自己的系统挤压”

**镜头 / 时间：** R51–58，125.567–147.267 秒。证据：sheet-09、10；`middle.js:R51–R58/errorScene/errorCard`。

**现状：** 请求、重试、错误归因和自造消息的逻辑完整，但约 21.7 秒多次返回同一个工作区。R51 的人物透明度只有 0.25，后续大半身体位于面板之后；许多文字在解释同一件事。R58 堆满红框有压迫效果，可是角色被遮住后，压力更像界面容量问题，身体与空间的损失不够突出。

**讨论提案：** 保留第一次完整请求用于建立规则，之后用三次有动机的镜头接力：点发送的动作 → 被拒绝的那个参数 → 沿拒绝连线退回到被面板挤住的手与旧星。前几张错误允许阅读，后几张转成实心前景 / 墙面，挡住她实际能活动的空间。R57 的紫色笔迹来源揭穿应成为一次空间上的回望，而不是再添一个说明框。

**保留 / 验收点：** 重试 1–5、自行伪造输入、自己才是作者的事实不变；关键错误仍可读，非必要解释文字可减。压力升级要由同一动作的后果推动，不能只加乱抖、频闪或随机窗口。
