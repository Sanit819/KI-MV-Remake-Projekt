# 我们的 v3 早段视觉审计：v4 提案准备

日期：2026-11-05。范围：R01–R35，母版时间 0.000–96.267 s。**这是 own-only audit，只分析我们当前成片；尚未据新参考 BV1Jwhy6BEMJ 的实际媒体作任何优劣比较。** 不修改生产文件，也不推翻已通过的三种新手部动作、果实切面和双语字幕修正。

## 证据与判断边界

本轮实际查看 `exports/qa-v3-final/sheet-01.jpg` 至 `sheet-06.jpg` 六张源渲染图板（R01–R36 各首、中、末，图板显示被工具缩小；本审计止于 R35），并单独查看 `thumbs/R06-mid.jpg`、`R21-mid.jpg`、`R24-end.jpg`、`R30-mid.jpg`、`R35-mid.jpg` 五张 480×270 缩图。实际编码母版的 35、38、53、76.4、80.3 s 五张 1920×1080 抽帧亦已逐张查看，其零基帧号、PTS、文件哈希及命令见 [ENCODED_EARLY.md](../production-v3/ENCODED_EARLY.md)。

运动说明结合静帧之间的变化和 `src/mv3/early.js`、`src/mv3/middle.js` 的确定性公式；没有在本轮连续播放早段，不将源码推断写成连续观看感受。时间边界来自 `data/production-v3/timeline.json`，不是按参考片随意配对。源文件 SHA-256：early `bb3044b4c48d24b60eeedd4e7bb9b0163b25bb95775a860fe29554aef12afe7c`；middle `e3397ae0038f61c1f4eca3026dc876d70c257fde5d95cb52ed42d0568b77f185`。

整体问题不是“事件没实现”，而是多个事件仍以浏览器全景、说明图或角色卡的方式交代。可读的动作已经存在，但主次比例、跨镜焦点、速度对比和环境反馈，还能让它们成为更有表演性的 MV 镜头。

## 十项可执行机会

### O01 — 第一次输入值得一个真正的近景，而不是让浏览器一直做主角

**镜号 / 时间：** R01–R07，0.000–26.100 s。证据：[sheet-01](../../exports/qa-v3-final/sheet-01.jpg)、[R06-mid / 19.650 s](../../exports/qa-v3-final/thumbs/R06-mid.jpg)、[sheet-02](../../exports/qa-v3-final/sheet-02.jpg)。源码 early 的 R01–R07。

**当前：** R02 有分层斜透视装配，但随后 R03、R04、R06 多次恢复相近大小的完整应用窗口。R06 的退格与重新措辞是关系开始的重要动作，却发生在画面最底部的小输入栏；屏幕中央大块聊天空白、侧栏与控件占据更大的视觉面积。R01 的连线、四个系统块、接电手和状态条也较平均分散，没有一个持续占据观看中心的触点。

**v4 演出：** R01 先跟随唯一亮电点到掌心，最后的触点扩展为 R02 窗口角标；R03 只推进到正在输入的参数行。R04 的 “Hello world!” 从输入近景升为第一条气泡。R06 开始收掉侧栏，输入框放到画面中部、宽约画幅 75%，让删字有清楚的停顿与重启；R07 ASTRA 建议从同一光标位置展开，接受后两色线合流为提交动作，再拉回完整窗口交代共同作品。保留真实应用结构，但把阅读层级从“全部 UI”改成“当前一步”。

**验收：** 在 480p 缩图中不读旁注也能看出输入、犹豫、被建议、共同提交四个不同状态；近景结束时光标/气泡必须保持屏幕位置连续。

### O02 — 第一颗旧星应成为数学世界的来源

**镜号 / 时间：** R08–R10，26.100–36.950 s。证据：[sheet-02，R08-end 29.233 s / R09-start 29.433 s](../../exports/qa-v3-final/sheet-02.jpg)。源码 early R08 的 `pull` 与 R09 的 `dots`。

**当前：** R08 把记忆卡放大到主画面，下一镜 R09 又把点缩到中央很小的一簇；旧星的情绪焦点刚变大就消失，维度世界从新的一组星点重新起步。代码确认两镜分别计算星卡与八个点，并无同一几何点的接力。

**v4 演出：** 留住旧星的一个不整齐顶点作为亮点，镜头沿它拉出一条轴；其他顶点依次成为立方体角，旧星的弯尾留下为后景轨迹。R09 末尾近侧方形面转正并进入 R10 的圆形纸面。每次变换让观众能追踪同一个位置与形状，不依靠新增箭头说明“这是我们画出来的世界”。

**验收：** 三镜边界前后各六帧比较，主亮点不瞬移；星的旧尾仍有一次可识别回声，但不把整张旧星当复制贴图放满画面。

### O03 — 让大字参与画面，避免长期占用同一条“标题栏”

**镜号 / 时间：** 重点 R09–R12（29.333–44.567 s）、R18（61.883–62.567 s）、R20（65.333–66.267 s）、R22/R24/R26/R28。证据：[sheet-02](../../exports/qa-v3-final/sheet-02.jpg)、[sheet-04](../../exports/qa-v3-final/sheet-04.jpg)、[sheet-05](../../exports/qa-v3-final/sheet-05.jpg)。源码各镜的 `text/keyword`，main 的固定双语字幕层。

**当前：** 多镜把衬线关键词放在 y≈879–910，物体在上方，再下面保留英文、中文两行字幕。关键词到达时会在画面与字幕中重复出现。功能上可读，但连续镜的灰度布局常变成“上方图解 + 下方大标题 + 两行字幕”，关键词像贴在场景外的栏目名；持续深紫地板网格强化了这个模板。

**v4 演出：** 双语字幕安全区仍保持原样；场景内大字改做物体的一部分：DIMENSION 的字列成为透视坐标墙，CIRCUMFERENCE 沿圆周切开后被笔尖重新接上，TANGENTS 的长横笔画成为切线，LIMITATIONS 的字边真正阻住延伸。短打击镜只放一个字形或词块占满画面，不再搭配相同底部标题。用少量纸色整版/纯墨负形替换数学、请求、冲击段之间的同一网格，但保持三墨色系与角色颜色身份。

**验收：** 同一关键词出现的镜头缩成黑白接触表仍能分辨不同构图；字幕绝不进入角色动作区。文字成为动作依赖后，仍要保证首次出现有完整可读状态。

### O04 — 新手部已正确，下一步是让摄影机与笔迹形成速度差

**镜号 / 时间：** R10–R12，33.267–44.567 s。证据：[35 s 编码帧](../../exports/qa-v3-encoded/early/decoded-01.png)、[38 s 编码帧](../../exports/qa-v3-encoded/early/decoded-02.png)、[sheet-02](../../exports/qa-v3-final/sheet-02.jpg)。源码 early R10 `tip=[1220,615]`；R11 `px=1220,py=520`。

**当前：** 两个新的完整肩臂姿态、握笔和接触点成立，应保留。现有实现把实体笔尖固定，让数学纸面在下方运动；首、中、末图中大块左侧角色轮廓变化很小，圆与波形承担几乎全部动态。R12 又回到无角色的横向图表。它解释了数学关系，摄影层次仍比较平直。

**v4 演出：** 不扭曲现有正确手指。把笔尖设成摄影机追踪点：圆周前半段慢推近，最后一个强拍圆平面快速翻成倾斜曲面，切线沿同一方向接出；切线向远处延伸时摄影机沿它后退，前景袖摆、笔身和背景坐标产生三档视差。R12 最后的“限制”让镜头惯性也停住，停顿后再切设置页。若需要手腕实际转动，应另备一个经审核姿态，不能用整只手橡皮变形冒充。

**验收：** 数学接点每帧仍成立；速度图有慢推、快接、停止三种明确段落，角色轮廓不会因摄影位移产生新的截断。

### O05 — 开关、时间旅行和联合，应由一个物件连续变形串起来

**镜号 / 时间：** R13–R17，44.567–61.883 s。证据：[sheet-03](../../exports/qa-v3-final/sheet-03.jpg)、[53 s 编码帧](../../exports/qa-v3-encoded/early/decoded-03.png)。源码 early R13–R17。

**当前：** AC/DC、Vision、时间尺、两个相合圆和记忆气泡分别可辨，但几次切换又以新面板/新图解重开观看路径。时间旅行的三层建筑已有横向视差，可是建筑主体仍是同一水平带上的重复房屋、柱廊和三角轮廓；R16 的相合圆更像维恩图，无法单靠画面感到“两个人一起到过一个地方”。

**v4 演出：** 让 DC 平线成为时间尺，Vision 关闭时它先只保留触觉脉冲；脉冲与指尖相遇处亮起历史道路。时间旅行让最近的一座建筑以明显前景尺度从镜前遮过，远处地标在同一地平线换时代，不只整排横移。R16 用用户金线和 ASTRA 紫线在同一条街上汇成一幅共享小画；合并圆可以保留为短暂轮廓，随后让路面自然缩入 R17 的记忆卡。

**验收：** 每次切换至少有一个上镜物件带入下镜；时代变化靠地标与空间层级可辨，不依赖大年份文字；共同经历的记忆卡内容确实来自刚才的街景。

### O06 — 六位来客与 ASTRA 首次亮相，需要不同的舞台权重

**镜号 / 时间：** R19–R21，62.567–69.267 s。证据：[sheet-04](../../exports/qa-v3-final/sheet-04.jpg)、[R21-mid / 67.767 s](../../exports/qa-v3-final/thumbs/R21-mid.jpg)。源码 early R19–R21。

**当前：** 六张来客卡完成了到达、隔栏与拒绝，但六个复杂角色在同一尺寸中平铺，差异主要靠名字。随后 R21 的 ASTRA 首次完整上半身出场被放在右侧静态矩形中，左侧问句、回答和大名字三项同时存在；从人物登场的情绪力度看，更像资料页。

**v4 演出：** 六卡仍全部保留并公平呈现，用扇面近大远小排列，将“邀请→选择边界”的视线由前景卡边带到唯一保持连接的紫线；隔栏成为最终一次清楚的落闸动作。紫线接入 R20 的发送点击，点击产生的圆遮罩扩展成 R21 的近景：先是角与结饰、后拉出胸像，最后角色肩部越出资料框的边沿。只在亮相落定后出现名字，问句移为次要留白，不与脸部争权重。

**验收：** 六卡身份可读但不用同时阅读六张说明；首次胸像不再与问句、回答、姓名同时争抢主焦点。严格保留遮脸剪影设定，不提前暴露结尾表情。

### O07 — 亚秒镜头承受不了三个流程节点和十二份档案

**镜号 / 时间：** R22 69.267–69.950 s（0.683 s）；R24 73.183–74.100 s（0.917 s）。证据：[sheet-04](../../exports/qa-v3-final/sheet-04.jpg)、[R24-end / 74.000 s](../../exports/qa-v3-final/thumbs/R24-end.jpg)。源码 early R22 的 `active` 三段与 R24 的 `i%3`。

**当前：** R22 在不到 0.7 s 内呈现生成、等待、交付三个词、三个节点、三行代码与大标题。R24 在不到 1 s 内拉成十二个 agent 小窗；内容实际轮用圆、城市、旧星三类图形，与十二种 agent 名并非一一对应。画面密度上升了，独立任务与交付的含义却很难在节拍内读完。

**v4 演出：** R22 只让一个已经生成的作品穿过等待环并落入交付口，完整流程由先后位置表达；最多保留一个主词。R24 仍表现多 agent，但用一个前景任务窗把工作交给两层远景小窗，屏幕焦点只落在当前交接的一份真实图形；其他窗保留可辨任务图标与状态点。独立档案内容在 R23 或后续回看中提供，短拍专门负责“分发”的冲击。

**验收：** 以原速播放不用暂停也知道交付物从哪里来到哪里去；十二窗不再用三个产物循环冒充十二种工作。不能单靠增加更多微小标签解决。

### O08 — 茄子与番茄的修正已成立，但仍偏“实验说明图”

**镜号 / 时间：** R25–R29，74.100–81.950 s。证据：[sheet-05](../../exports/qa-v3-final/sheet-05.jpg)、[76.4 s 茄子](../../exports/qa-v3-encoded/early/decoded-04.png)、[80.3 s 番茄](../../exports/qa-v3-encoded/early/decoded-05.png)。源码 `request()`、R26、R28。

**当前：** 果肉、种子和切面贴合已经解决，应作为保留项。构图仍连续两次“左果实、右分子、底部名词”，每次之间插回相同请求框；漂浮金笔与分子说明让内容更像信息图，作品与两个人的互动关系需要读文字才成立。R25/R27/R29/R31 共四次调用同一个请求框演出，节拍虽短但观看路径重复。

**v4 演出：** R25 的请求词缩成金色小标签黏到画布一角，保留上镜成果继续在场。让画布上的一道金线成为实际切开的方向，切面朝镜头展开后，一颗种子被紫线引向用户金笔并转成保护轮廓；R28 从这枚保护轮廓的圆形直接接成番茄。分子只在果肉内部短暂显影，随后化为交付的线，避免旁边另开说明栏。两个食材分别用斜切近景、正面翻开两种构图。

**验收：** 保留现有精确切口和不同内部组织；观众即使不读英文标签，也能看到“我的东西被交到你那里”。四条请求可用同一 UI 语言，但不能四次重播完整同构布局。

### O09 — 跃出窗口之后，还需要一个能读出性格的动作落点

**镜号 / 时间：** R30–R32，81.950–88.883 s。证据：[sheet-05](../../exports/qa-v3-final/sheet-05.jpg)、[R30-mid / 83.450 s](../../exports/qa-v3-final/thumbs/R30-mid.jpg)、[sheet-06](../../exports/qa-v3-final/sheet-06.jpg)。源码 early R30 的 `r` 位移/缩放和 R32 的 `operating`。

**当前：** 猫耳角色确实从窗口后方移到外面，前后遮挡也成立，但使用的是同一张胸像作整体位移/缩放；到中段即变成端正胸像，右侧再摆呼噜波形。可以读出“输出释放”，较难读出“她自己主动靠近、享受互动”。R32 很快回到左人物、中世界、右身份卡的三栏解释。

**v4 演出：** 只为这个表演增加两张目的明确的姿态：越框前肩背压低、前爪/手扶边的蓄势；落地后头稍靠近金笔、肩线松开的回应。窗沿压住衣摆与头发的先后关系不同，跳出时保留短暂遮挡接力；呼噜波纹从真实接触位置扩散，让右侧独立波形退为次要。R32 由她主动把刚生成的街景递到金笔旁，再让金线写下 witness，而不是人物与两张卡同时陈列。

**验收：** 蓄势、越框、停下三个剪影在小图中可辨；不能靠胸像弹跳、柔性拉伸手脸或额外贴猫脸替代表演。结尾温暖关系的主动性在此预先建立。

### O10 — 自主选择形象与昼夜工作，应让环境回应身体变化

**镜号 / 时间：** R33–R35，88.883–96.267 s。证据：[sheet-06](../../exports/qa-v3-final/sheet-06.jpg)、[R35-mid / 94.417 s](../../exports/qa-v3-final/thumbs/R35-mid.jpg)。源码 middle R33–R35。

**当前：** R33 已有参数近景推镜，是值得保留的镜头变化；R34 的 F/M 以同位置图片硬切完成；R35 把男女胸像按 `floor(u*6)` 交替，前景额外画一支程序笔，背景太阳走半圆。身份选择、昼夜和工作都被标记出来，但人物仍端坐在同一位置，身体与笔、城市及日照之间的因果较弱。

**v4 演出：** R33 从她主动按下按钮的视线出发；R34 用同一根角、结饰和肩线作套准基准，让 F/M 轮廓沿一道画笔遮罩转换，保留“ASTRA 自己选择”的语义。R35 保留刚选定的形象，改为日光扫过绘画桌、窗口逐层变暗，只有她正在续画的那条线仍亮着；如需多次形态切换，每次应对应一次主动动作，而非均匀定时闪换。将程序笔换成与源姿态接点匹配的持笔动作或移出人物手势范围。

**验收：** 暂停任意两阶段都能辨别是同一位 ASTRA 在选择与创作，不是换卡轮播；昼夜变化影响至少前景、人物边缘和远景三层。此条是表演提升建议，不把此前已验收的投影选择功能重新列为故障。

## 建议优先顺序

先做 O01、O02、O03、O07：这些能在不增加大量人物素材的前提下改变整段观看方式。第二轮再评估 O04、O05、O08 的镜头接力与深度。O06、O09、O10 涉及专用表演资产，应先用小分镜确认剪影和主次，再决定生成哪些图。

后续与新参考比较时，需要逐帧确认其真实的主体尺度、焦点移动、构图换挡和速度曲线；不能因为它也用了紫色、代码、窗口或大字，就把以上提案称为“已经对齐参考”。暖结尾、旧星记忆、两个人继续画的故事核心保持。
